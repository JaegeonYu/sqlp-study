# 미니 모의 2 — 옵티마이저 · 쿼리 변환

- 범위: 8주차(옵티마이저 원리), 9주차(쿼리 변환)
- 시간: 필기 15분 + 실기 30분
- 정답과 해설은 스터디 당일 이후 진행자가 공개합니다. 답안은 `submissions/<id>/mock.md`에 적습니다.

## 필기 (5문항)

**1.** 히스토그램이 없는 컬럼 `C`(NDV = 4, NULL 없음, 테이블 100만 건)에 `C = :b` 조건을 걸었을 때 옵티마이저가 추정하는 카디널리티는?
1. 1
2. 4
3. 250,000
4. 1,000,000

**2.** 바인드 변수와 히스토그램에 대한 설명으로 **틀린** 것은?
1. 바인드 피킹은 하드 파싱 시점의 바인드 값으로 실행계획을 정한다.
2. Adaptive Cursor Sharing은 바인드 값의 선택도에 따라 child cursor를 새로 만들 수 있다.
3. 히스토그램이 없는 컬럼이라면 바인드 피킹 결과가 실행계획에 영향을 주지 않는다.
4. ACS가 동작하면 첫 실행부터 바인드 값마다 최적의 계획이 보장된다.

**3.** 다음 중 서브쿼리 Unnesting을 **막는** 힌트는?
1. `UNNEST`
2. `NO_UNNEST`
3. `PUSH_SUBQ`
4. `HASH_SJ`

**4.** 아래 SQL에서 옵티마이저가 `E.DEPT_NO = 10` 조건을 스스로 만들어 내는 변환은?
```sql
select * from emp e, dept d
where e.dept_no = d.dept_no and d.dept_no = 10;
```
1. 뷰 머징
2. 조건절 이행
3. 조인 제거
4. OR-Expansion

**5.** 조인 제거(Join Elimination)가 일어나기 위한 조건으로 거리가 **먼** 것은?
1. 부모 테이블의 컬럼을 SELECT 절이나 조건절에서 참조하지 않는다.
2. 자식 테이블의 조인 컬럼에 FK 제약이 있다.
3. 자식 테이블의 조인 컬럼이 NOT NULL이거나, 바깥 조인이다.
4. 자식 테이블의 조인 컬럼에 인덱스가 있다.

## 실기 (1문항)
`03_challenge.sql`을 실행해 원본 SQL의 실행계획을 확인한 뒤 답합니다.
1. 원본이 비효율적인 이유를 실행계획 근거(오퍼레이션, A-Rows, Buffers)로 서술합니다.
2. 결과는 같게 유지하면서 읽는 양을 줄인 SQL을 작성합니다. 인덱스가 필요하면 DDL도 함께 씁니다.
3. Before/After의 Buffers와 A-Time을 비교하고, 개선된 이유를 쿼리 변환 관점에서 설명합니다.

채점 기준: 원인 진단 30%, 튜닝 SQL·인덱스 설계 40%, 수치 근거와 설명 30%

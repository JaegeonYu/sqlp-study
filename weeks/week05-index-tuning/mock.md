## 필기 (5문항, 4지선다)

**1.** 클러스터링 팩터(CF)에 대한 설명으로 가장 적절한 것은?
1. CF가 테이블 행 수에 가까울수록 인덱스 범위 스캔의 테이블 액세스 효율이 좋다.
2. CF는 인덱스 리프 블록 수와 같다.
3. CF가 테이블 블록 수에 가까울수록 인덱스 순서와 테이블 저장 순서가 비슷하다.
4. CF는 인덱스를 재생성(rebuild)하면 항상 좋아진다.

**2.** 인덱스 `(A, B)`에서 `WHERE A BETWEEN :x AND :y AND B = :z` 조건을 처리할 때 옳은 것은?
1. A와 B가 모두 인덱스 스캔 범위를 줄인다.
2. A는 스캔 범위를 정하고, B는 스캔 중 걸러내는 조건으로 주로 쓰인다.
3. B가 선두가 아니므로 인덱스를 사용할 수 없다.
4. 옵티마이저는 항상 Index Skip Scan을 선택한다.

**3.** 다음 중 인덱스 `IX(ORDER_DT)`를 Range Scan으로 사용할 수 **있는** 조건은? (`ORDER_DT`는 DATE)
1. `TO_CHAR(ORDER_DT, 'YYYYMMDD') = '20250101'`
2. `ORDER_DT + 1 > SYSDATE`
3. `ORDER_DT >= TO_DATE('20250101', 'YYYYMMDD')`
4. `NVL(ORDER_DT, SYSDATE) > SYSDATE - 7`

**4.** 인덱스 손익분기점(인덱스 액세스가 Full Scan보다 불리해지는 지점)에 영향을 주는 요소로 거리가 **먼** 것은?
1. 클러스터링 팩터
2. 버퍼 캐시 히트율과 Multiblock I/O 크기
3. 조회 대상 행의 비율
4. 결과 집합을 클라이언트에 전송하는 문자셋

**5.** Index Fast Full Scan에 대한 설명으로 옳지 **않은** 것은?
1. 인덱스 세그먼트 전체를 Multiblock I/O로 읽을 수 있다.
2. 결과가 인덱스 키 순서대로 정렬되어 나온다.
3. 쿼리에 필요한 컬럼이 모두 인덱스에 있어야 사용할 수 있다.
4. 병렬로 처리할 수 있다.
